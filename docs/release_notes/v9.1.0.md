# gospice v9.1.0

gospice v9.1.0 binds more Go types as query parameters and has fewer restrictions on the API key field, so it connects to self-managed Spice runtimes that require an API key. It also uses one Flight session for each client, and HTTP errors now include the message from the runtime. This release is source-compatible with v9.0.0. Read [Behavior changes](#behavior-changes) before you upgrade.

## 🎯 Features

### `time.Time` and `time.Duration` parameters

`SqlWithParams` now infers `time.Time` and `time.Duration` parameters. Before, these failed with `unsupported parameter type: time.Time`, and you had to use `NewTypedParam`. ([#93](https://github.com/spiceai/gospice/pull/93))

```go
reader, err := spice.SqlWithParams(ctx,
    "SELECT COUNT(*) FROM taxi_trips WHERE tpep_pickup_datetime >= $1",
    time.Date(2024, 1, 31, 0, 0, 0, 0, time.UTC))
```

- `time.Time` binds as `Timestamp(ns, "UTC")`, after conversion to UTC. `time.Duration` binds as `Duration(ns)`.
- A `time.Time` that is not in the range 1677-09-21 to 2262-04-11 returns an error.

### Pointers, `sql.Null*` types and named types

`SqlWithParams` now accepts parameter values in the forms that Go code usually holds them. ([#94](https://github.com/spiceai/gospice/pull/94))

| Value | Binds as |
|---|---|
| `*T` (any depth) | The value that it points to |
| A nil `*T` | A NULL with the type of `T` (a nil `*int64` is an `Int64` NULL) |
| `sql.NullInt64`, `NullInt32`, `NullInt16`, `NullByte`, `NullFloat64`, `NullBool`, `NullString`, `NullTime`, `sql.Null[T]` | The value, or a typed NULL when `Valid` is false |
| Another `driver.Valuer` | The value that `Value()` returns |
| A named type of a basic kind (`type VendorID int64`) | The underlying kind |

```go
type VendorID int64
var minFare *float64 // nil: no lower bound

reader, err := spice.SqlWithParams(ctx,
    "SELECT * FROM taxi_trips WHERE VendorID = $1 AND ($2 IS NULL OR fare_amount >= $2) LIMIT 10",
    VendorID(2), minFare)
```

## 🔧 Fixes

### Fewer restrictions on the API key field for self-managed runtimes

`WithApiKey` now has fewer restrictions on the API key value. Before, the key had to use the Spice Cloud format `appId|secret`. Now the client accepts any value that is not empty. Thus you can connect to a self-managed Spice runtime that has [API key authentication](https://spiceai.org/docs/api/auth) enabled. Before, a key for a self-managed Spice runtime failed in `Init` with `apiKey is invalid`, and an `app|key` workaround failed with `Invalid handshake request`. ([#95](https://github.com/spiceai/gospice/pull/95))

- When you send the key to a self-managed Spice runtime (an address that is not Spice Cloud), or when the key does not use the `appId|secret` format, the key goes out as `authorization: Bearer <key>` on each Flight call, with no handshake. `SqlWithParams` (ADBC) sends the same header. HTTP calls continue to send `X-API-Key`.
- A Spice Cloud key (`appId|secret`) that you send to Spice Cloud continues to use the Basic handshake.

### The runtime's error message in HTTP errors

`RuntimeStatus`, `ListActiveQueries`, `CancelActiveQuery` and `RefreshDataset` now include the error message from the runtime. Before, they gave only the HTTP status code. `RefreshDataset` printed an empty `body=`. ([#87](https://github.com/spiceai/gospice/pull/87))

```
before: POST http://127.0.0.1:8090/v1/datasets/orders/acceleration/refresh failed with status=404. body=
after:  the error includes: dataset 'orders' not found
```

### `Search` rejects a response that is not a search response

`Search` now returns an error when a `200` response does not have the fields that the runtime always sends (`results`, `duration_ms`, and for each match `dataset`, `_score` and `matches`). Before, a response such as `{}`, or an error body from a proxy, gave an empty result and no error. A `score` field from an older runtime now reads correctly. Before, it read as `0`. ([#91](https://github.com/spiceai/gospice/pull/91))

## ⚡ Performance

### One Flight session for each client

The client now does the authentication handshake one time for each `SpiceClient`, and uses the same session for `Sql`, `Query` and each async query action. Before, it did a handshake before each call and before each retry. When the runtime does not recognize the session, the client gets a new session one time and continues. A rejected API key is not retried. ([#89](https://github.com/spiceai/gospice/pull/89))

## Behavior changes

- **The default HTTP endpoint now follows the Flight endpoint.** A client that uses the local Flight endpoint now sends its HTTP calls (`IsSpiceHealthy`, `IsSpiceReady`, `RefreshDataset`, `Search`, `Nsql`, `RuntimeStatus` and the active-query calls) to `http://127.0.0.1:8090`. Before, these calls went to Spice Cloud. ([#88](https://github.com/spiceai/gospice/pull/88))

  This affects only one configuration: `Init(WithApiKey(key))` with no `WithSpiceCloudAddress()`. Its HTTP calls went to Spice Cloud, and now go to the local runtime. To keep the old behavior, add `WithSpiceCloudAddress()`, or `WithHttpAddress("https://data.spiceai.io")`. `WithSpiceCloudAddress()` and `WithHttpAddress()` work as before.

## 📖 Documentation

- All Go examples in the README compile. The record-iteration examples no longer release batches that the reader owns. `example_test.go` makes sure that the quickstart continues to compile. ([#90](https://github.com/spiceai/gospice/pull/90))
- Search `Keywords` are described correctly: each keyword is a case-insensitive filter on the searched column before the vector search. They do not add a hybrid ranking. ([#96](https://github.com/spiceai/gospice/pull/96))
