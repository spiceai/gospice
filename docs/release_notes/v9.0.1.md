# gospice v9.0.1

Patch release for two silent-failure / documented-path bugs in parameterized queries and client initialization.

## Breaking Changes

- **`Decimal128Param` / `Decimal256Param` byte order is now Apache Arrow little-endian.** v9.0.0 decoded a `Decimal128Param` `[16]byte` as big-endian two's complement, and a `Decimal256Param` `[32]byte` as little-endian words passed to `decimal256.New` in reverse (most-significant word last). Arrow-native little-endian bytes for `1.0000000001` therefore bound as `251330144182111795843047163.8248062976` (128-bit) or `6277101736014390937374457499591245358423122086074270057342.4034512896` (256-bit), so a filter such as `WHERE amt = $1` matched nothing — or the wrong row. Both helpers now document and use Arrow-native little-endian two's complement (least-significant 64-bit word first). Callers that assembled bytes to match the old decoder must switch layout, or pass a `decimal128.Num` / `decimal256.Num`.

## Fixed

- **`Decimal128Param` / `Decimal256Param` bind the intended value.** Decoding is Arrow little-endian at both widths. `decimal128.Num` and `decimal256.Num` are accepted by type inference (defaults `(38, 10)` and `(76, 10)`) and by the builders. `DecimalParam(num, precision, scale)` sets precision and scale without assembling bytes.
- **`SetMaxRetries(0)` no longer makes `Init` fail.** The documented "disable retries" path emitted a gRPC `retryPolicy` with `MaxAttempts: 1`, which grpc-go rejects (`MaxAttempts` must be `>= 2`) as `invalid retry policy`. When retries are 0 the Flight service config omits `retryPolicy` and the app-level backoff wrapper is skipped, so `Init` succeeds and a failing call is attempted once.

## Added

- `DecimalParam(value, precision, scale)` for `decimal128.Num` and `decimal256.Num`.
