# Announcing gospice v8.0.0 - Cleaner API & Health Checks 🚀

gospice v8.0.0 introduces a cleaner API with new `Sql()` and `SqlWithParams()` methods, along with robust health check methods. This major release brings improvements in developer experience while maintaining full backward compatibility.

## 🎯 Major Features

### Cleaner API

gospice v8 introduces simpler, more intuitive method names:

```go
// New recommended methods
reader, err := spice.Sql(ctx, "SELECT * FROM users")
reader, err := spice.SqlWithParams(ctx, "SELECT * FROM users WHERE id = $1", userId)

// Old methods still work for backward compatibility
reader, err := spice.Query(ctx, "SELECT * FROM users")
```

**Why the change?**

- Shorter, more intuitive names
- Better alignment with SQL standard naming
- Cleaner, more readable code

### Parameterized Queries

The `SqlWithParams` method enables safe, parameterized queries:

```go
// Safe from SQL injection with automatic type inference
reader, err := spice.SqlWithParams(
    ctx,
    "SELECT * FROM blocks WHERE number > $1 AND hash = $2",
    blockNumber,
    blockHash,
)
```

**Automatic type inference for common Go types:**

- Integers: `int`, `int8`, `int16`, `int32`, `int64`, `uint`, `uint8`, `uint16`, `uint32`, `uint64`
- Floating point: `float32`, `float64`
- String: `string`
- Boolean: `bool`
- Binary: `[]byte`
- Null values: `nil`

### Typed Parameters (New in v8!)

For advanced use cases requiring precise type control, gospice v8 introduces **typed parameter constructors** that give you explicit control over Arrow types:

```go
// Precise type control for complex data types
reader, err := spice.SqlWithParams(
    ctx,
    "SELECT * FROM financial WHERE amount >= $1 AND timestamp > $2",
    gospice.Decimal128Param(amountBytes, 19, 4),  // Decimal with precision & scale
    gospice.TimestampParam(ts, arrow.Microsecond, "UTC"),  // Timestamp with unit & timezone
)
```

**Available typed constructors:**

- **Integers**: `Int8Param`, `Int16Param`, `Int32Param`, `Int64Param`, `Uint8Param`, `Uint16Param`, `Uint32Param`, `Uint64Param`
- **Floating point**: `Float16Param`, `Float32Param`, `Float64Param`
- **Strings**: `StringParam`, `LargeStringParam`
- **Binary**: `BinaryParam`, `LargeBinaryParam`, `FixedSizeBinaryParam`
- **Boolean**: `BoolParam`
- **Date/Time**: `Date32Param`, `Date64Param`, `Time32Param`, `Time64Param`, `TimestampParam`, `DurationParam`
- **Intervals**: `MonthIntervalParam`, `DayTimeIntervalParam`, `MonthDayNanoIntervalParam`
- **Decimals**: `Decimal128Param`, `Decimal256Param`
- **Null**: `NullParam`

**Generic constructors:**

- `NewParam(value)` - Automatic type inference
- `NewTypedParam(value, arrowType)` - Custom Arrow type specification

### Health Check Methods

New health check methods for verifying Spice instance status:

```go
// Check if instance is healthy (unauthenticated)
if !spice.IsSpiceHealthy(ctx) {
    log.Fatal("Spice instance is not healthy")
}

// Check if instance is ready (requires API key)
if !spice.IsSpiceReady(ctx) {
    log.Fatal("Spice instance is not ready")
}
```

**Features:**

- `IsSpiceHealthy(ctx)` - Checks `/health` endpoint (no auth required)
- `IsSpiceReady(ctx)` - Checks `/v1/ready` endpoint (requires API key)
- Validates response body content ("ok" and "ready" respectively)
- Useful for health monitoring, startup checks, and graceful test skipping

## 📦 What's Changed

### New Methods

- **`Sql(ctx, sql)`** - Execute SQL queries (recommended, replaces `Query`)
- **`SqlWithParams(ctx, sql, params...)`** - Execute parameterized queries (recommended, replaces `QueryWithParams`)
- **`IsSpiceHealthy(ctx)`** - Check instance health (unauthenticated)
- **`IsSpiceReady(ctx)`** - Check instance readiness (requires API key)

### Upgraded Dependencies

- Upgraded to **Apache Arrow v18** (from v17)
- Added **ADBC Go driver v1.3.0**
- Updated Flight SQL driver for ADBC compatibility

### Backward Compatibility

✅ The existing `Query` method continues to work for non-parameterized queries
✅ All existing client initialization methods remain unchanged
✅ Flight SQL queries still supported alongside ADBC

### Quick Start

```go
import "github.com/spiceai/gospice/v8"

// Initialize client (same as before)
spice := gospice.NewSpiceClient()
defer spice.Close()

if err := spice.Init(
    gospice.WithApiKey(apiKey),
    gospice.WithSpiceCloudAddress(),
); err != nil {
    panic(err)
}

// Use the new methods
reader, err := spice.SqlWithParams(
    ctx,
    "SELECT * FROM tpch.customer WHERE c_custkey > $1 LIMIT 10",
    100,
)
```

### When to Use Each Method

| Use Case                | Method (v8)     | Legacy Method     | Example                        |
| ----------------------- | --------------- | ----------------- | ------------------------------ |
| Static queries          | `Sql`           | `Query`           | `SELECT * FROM table LIMIT 10` |
| Queries with parameters | `SqlWithParams` | `QueryWithParams` | `SELECT * WHERE id = $1`       |

## 🔒 Security Improvements

Parameterized queries provide protection against SQL injection attacks:

```go
// ❌ Vulnerable to SQL injection
userId := getUserInput() // Could be: "1 OR 1=1"
sql := fmt.Sprintf("SELECT * FROM users WHERE id = %s", userId)
reader, err := spice.Sql(ctx, sql)

// ✅ Safe from SQL injection
reader, err := spice.SqlWithParams(ctx,
    "SELECT * FROM users WHERE id = $1",
    userId,
)
```

## 🎓 Examples

### Example 1: Filtering with Multiple Parameters (Automatic Type Inference)

```go
reader, err := spice.SqlWithParams(
    ctx,
    `SELECT * FROM taxi_trips
     WHERE trip_distance > $1
     AND fare_amount > $2
     AND payment_type = $3
     LIMIT 100`,
    5.0,           // minimum distance (float64)
    20.0,          // minimum fare (float64)
    "Credit Card", // payment type (string)
)
```

### Example 2: Complex Query with Timestamps

```go
reader, err := spice.SqlWithParams(
    ctx,
    `SELECT
        date_trunc('hour', pickup_datetime) as hour,
        COUNT(*) as trip_count,
        AVG(fare_amount) as avg_fare
     FROM taxi_trips
     WHERE pickup_datetime BETWEEN $1 AND $2
     AND trip_distance > $3
     GROUP BY hour
     ORDER BY hour`,
    startTime,   // time.Time or arrow.Timestamp
    endTime,     // time.Time or arrow.Timestamp
    minDistance, // float64
)
```

### Example 3: Using Typed Parameters for Precision

```go
// Financial data requiring precise decimal types
reader, err := spice.SqlWithParams(
    ctx,
    `SELECT * FROM financial_transactions
     WHERE amount >= $1
     AND transaction_date >= $2
     AND account_id = $3`,
    gospice.Decimal128Param(amountBytes, 19, 4),  // Decimal(19,4) for currency
    gospice.Date32Param(startDate),                // Date32 for dates
    gospice.Int64Param(accountId),                 // Explicit int64
)
```

## 💡 Tips

1. **Always use `QueryWithParams`** for queries with dynamic values
2. **Use positional placeholders** (`$1`, `$2`, etc.) in your SQL
3. **Type safety** - gospice automatically converts Go types to Arrow types
4. **Connection management** - ADBC connections are managed automatically
5. **Error handling** - Check for parameter binding errors separately from query errors
